# Working on SysPane

Start with `spec/delivery/current-state.md`, the current user instruction and the
selected row in `spec/delivery/work-units.json`. Read a row's linked package before
implementation. `spec/` owns contracts; `source/` owns implementation; `docs/` owns
user/developer guidance. Use one source tree and explicit component dependencies.

Use the ordinary commands in `docs/developers/build.md`. Preserve fixed acceptance
oracles, failures and blocked native qualification. Record source-bound evidence
and the next step. A dependency-ready row is not evidence of completion.

The admitted foundation campaign is recorded in
`spec/delivery/campaign-admission.md`. Routine reversible engineering choices within
that instruction do not require repeated permission. It does not authorize public
releases or privileged operations. AIDE remains optional and inactive.

Keep generated outputs inside owned, ignored `out/` roots. Inspect resolved paths
before cleanup. Do not reset unrelated work or introduce parallel copies of the
specification, runtime or work scheduler.

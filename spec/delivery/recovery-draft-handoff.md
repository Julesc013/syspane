# Generation-bound recovery draft checkpoint

Baseline 103c7d53f73b1d36dd1649b1f2a3a437dcf8c604. The
[shared package](packages/w-10-recovery-draft.md) adds bounded capture, inspection
and explicit restoration to EditorDraft. Its
[native Apply package](packages/w-10-recovery-apply.md) supplies the verified Linux
generation identity and exercises the existing durable transaction owner.

The trusted host provides profile and generation identity separately from the
untrusted recovery bytes. Current history/sensitive disclosure, editor.recovery,
large-command, resource and ordinary editor authority apply on every operation.
A record contains one preview scene command and exact content pins. It excludes
selection, history, pending requests, private input and operational observations.
The 786432-byte envelope and existing 327680-byte command ceilings are independent.

Only a pristine editable destination accepts restoration. Identity, revision,
root metadata, version, resource closure and current policy must agree. Restoring
creates one undo step, clears selection and reconstructs exact canonical font
artifacts through the existing theme owner. Original package allocations remain
shared. Inspection changes no draft state and grants no later permission. Neither
operation commits or activates content. Apply emits an ordinary fresh request.

LinuxGenerationStore::generation_token identifies the exact verified selecting
record of the loaded snapshot. Empty, damaged, fallback and indeterminate owners
refuse it. Reopening verifies the generation again. A token read does not perform
another filesystem lookup or claim to detect later external modifications; ordinary
publication retains its existing guards.

## Preserved failures and workspace evidence

The first shared build failed an unused test-helper warning; a versioned-baseline
recovery case now exercises that helper. Initial native configuration exposed a
target-name collision with the existing independent RecoveryProbe. The new editor
experiment has its own target, without changing that recovery supervisor.

The first native Apply attempt sent an ordinary content command through a harness
path with no imported resource catalog. It correctly returned content.capacity and
left revision 40 intact. The harness now supplies the declared catalog for ordinary
content commands and uses the retained-resource theme path for font commands. All
fixed scene, resource and acceptance expectations remain unchanged.

Native CONTENT-COMMANDS timed out on a replacement request in PREPARE-HANG; its
isolated unchanged follow-up passed all ten cases. The cause is unproven. A later
content-properties cancellation case hit a dbind timeout while setting image height.
The unchanged content-properties follow-up passed. Keep both original records and subsequent observations; a passing rerun alone does
not establish native observation reliability or explain either failure.

Specification validation initially misclassified the frozen all-digit generation digest
as uint64 overflow. The checker now distinguishes only editor-recovery identity.generation;
other generation/revision counters retain overflow checks. Two new tooling tests cover
the exact scope and digest shape. The original failed validation and unchanged fixtures
are preserved.

The existing workspace reservation stopped a build before execution. Completed
owned filesystem recordings were compressed and verified byte-for-byte, including
link targets and FIFO metadata, before duplicate working directories were removed.
The archiver stopped on the first FIFO and later on a non-directory archive; its
subsequent runs explicitly handled those entry types. Completed Windows campaign
records moved to ignored evidence storage with every file hash verified. Original
failures and artifacts remain retained; the 7 GiB active allocation did not change.

## Verification boundary

and control/line limits, incompatible required-feature negotiation and independent

The native storage experiment uses actual process interruption at twenty publication
transitions, exact recovered documents/resources, lost source directories, denied

opaque bytes declared as PNG: this verifies resource identity and durability, not
image decoding. Activation remains pending and visible remains false.

Review additionally identified legacy-manifest admission as a way to omit a new
scene's resources. Added cases require coherent fallback after a checksummed format
downgrade and rejection of bare scene 0.3 initialization. Resource-bearing storage
is mandatory for this scene version; bootstrap starts from scene 0.2 and enters
the new format through its resource transaction. The original executable's failure
against the extended oracle is retained before verifying the corrected build.
An earlier Windows suite passed its assertions while those Linux-only contract
inputs changed. The source-stability guard invalidated that attempt; the final
Windows suite is rerun against frozen inputs rather than claiming it as final.
The historical compiler also exposed an ambiguous one-element initializer in the
migration fixture: its roots member became a string instead of an array. The
preserved diagnostic shows that invalid input before migration. Explicit array
construction restores the intended input; expected migration output and rejection
conditions are unchanged. All three final suites use that same fixture.

The independent owned X11/AT-SPI experiment combines labelled collection cells and
a text body differing from its editor title. Separately composed expected pixels
and complete accessible names cover replacement, policy loss, stale delivery,
regrant, fresh attachment and retained source loss. Deliberate old-pixel and old-name
controls must expose the corresponding erasure failure.

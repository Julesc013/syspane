# Installed editor recovery consumption

Use the existing frontend, EditorForm, recovery session and verified native worker.
For an authenticated current profile with recovery context, the host locally adds
editor.recovery to the form's capabilities and binds the exact session, profile,
generation, directory, policy revision and erase permission. Null context preserves
the existing unavailable notice and ordinary editing. No path, resource header,
environment variable or UI input creates authority. No extra worker or scheduler.

Loading and an undecided offer block editing and navigation. Restore prepares a
local preview and one undo step; Apply alone persists it. Keep preserves the exact
record and disables automatic replacement for that editor session. Discard requires
current erase permission and conditionally removes only the loaded record. Cancel
retires this session's owned capture before leaving, and preserves kept records.
Private property fields and modal inputs never enter a capture before admission
into the draft. Interrupted and invalid records remain explicit offers, with Restore
disabled when validation fails. Regrant never revives a previous task or proof.

## Request and retirement lifetime

The form's host submission callback receives the completed durable capture digest
as an optional value, captured before callback dispatch. Preserve the ordinary
submission callback for existing hosts. Do not call form methods reentrantly from
that callback. Kept and unavailable capture states submit null metadata. Existing
backend validation against the actual command remains mandatory.

On authenticated acceptance, refresh the profile before further recovery work.
Close and reap the old form's tasks before constructing the replacement. Preserve
a bounded saved-revision notice across this refresh; it may report only validated
durability, never infer activation or desktop visibility. Clear this notice on
navigation, another submission, manual reload or authority withdrawal. An unknown
result preserves the original request and cannot authorize retirement or repetition.

Bind an optional retirement digest only with current erase permission and valid
lowercase SHA-256 syntax. Load through fresh admission before deciding. A matching
record is conditionally retired; acknowledgement requires a durable completion and
observed child exit. A different or absent record completes the comparison decision
without deletion, and a different record remains offered. Failure or withdrawal
does not complete the decision. The host acknowledges only the current ready profile
serial; do not acknowledge pending, stale or withdrawn state. The receipt is metadata,
not authority. Closing, invalidation and rebinding clear exposed decision state.

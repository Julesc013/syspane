# Recovery limits and installed scheduling qualification

profile, actual backend and GTK form, native helpers and immutable expected inputs.

## Inputs and fixed meaning

its scene identity, metadata, original two widgets and pinned resources. Append 254
independent text roots with unique stable IDs, fixed layouts and literal content.
This reaches the existing 256-widget limit. Fill their body strings in ID order,
at most 1024 characters each, until canonical scene serialization is exactly 262144
bytes. No scene-metadata extension or invalid structure may stand in for a valid
large scene. Freeze canonical expected scene digests before changing production.

Use the real selecting-record digest only as the runtime recovery generation. A
valid record contains the canonical preview scene.replace command with the original
revision, policy generation, request identity and resource pins. At the 786432-byte
record limit, pad the outer JSON with spaces; canonical captured output after Restore
must remove that padding and preserve the exact candidate. Oversize input is refused.

For the 327680-byte command boundary, add a single command extension containing
literal padding to a maximum scene command. The command is structurally valid but
cannot reconstruct the editor's canonical scene-only operation; recovery must reject
it without adopting a scene. It is an invalid recovery offer, not a valid restore.
Do not invent extra operations or loosen reconstruction checks to manufacture a pass.

## Measurements and decision criteria

Each GUI-facing creation, poll, consumption, cancellation and close call retains the
100 ms limit. Record per-call timings, full source and artifact identity, expected
and observed input sizes, worker completion/error, controller epoch and native child
exit. The observer may finish bounded cleanup and record additional measurements
after a timing violation, but must return failure. A repeated run never erases it.
Case and family ceilings remain 45 and 600 seconds; a lost native response retains
the existing five-second observation deadline. Do not change helper, storage,
heartbeat, supervision or profile-transfer deadlines.

During preparation, repeatedly sample the live backend and task. Require the same
authenticated controller epoch and no spurious withdrawal. For close, observe acquired
work before cancellation, preserve suppressed delivery, and require actual closure
of the existing workers and their native children. Do not create an additional worker
or scheduler to hide measured blockage. Any scheduling redesign requires a precise
ownership/cancellation amendment and its own acceptance before implementation.

The integrated GTK experiment must exercise offers, Restore, capture, Undo/Redo,
Apply, policy erasure and close at the admitted limits. It must measure GUI work and
responsiveness as well as exact documents, rather than merely await eventual success.
Independent observations verify retirement, child exit and unchanged deadlines.
Keep the original 14 installed recovery cases and all prior literal oracles intact.

Use measured failures to select a focused implementation repair. Internal allocation,
immutable caching or algorithm choices are delegated only if they preserve complete
schema/semantic/resource/policy validation and opaque proof validity. No fabricated
pass, inflated budget, reduced scene limit or privileged operation is authorized.
Production controls stay disabled until both isolated and integrated qualification
pass. Native inspector, desktop/provider/lifecycle, other adapters and all five
complete release editions remain required.

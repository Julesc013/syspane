# Table composition reuse of exact native rasters

The ordinary maximum-table regression fails TRUNCATION at 102.502 ms while the
subsequent complete phase diagnostic passes. Painting remains a material cost,
including repeatedly drawing identical configured Kind cells. Test a bounded
composition-local repair; neither timing sample establishes its cause alone.
Keep all existing ordinary cases, 100-ms GUI/200-ms erasure bounds, Debug profile,
font identities, table/frame/glyph/pixel limits and independent expected rows.

Within raster_table only, up to sixteen lookup entries may borrow immutable
source text and reference the function's already-owned native raster parts.
Reuse only an exact text/role match with empty semantic blocks. Theme, language,
token, contrast, font proof, scale and wrapping are fixed for the whole call.
Different roles remain distinct under theme 0.2.0; theme 0.1.0 uses its existing
body role. No request is deferred and no index, borrowed string or raster escapes
the call. The normal table output contains the same composed bytes and rectangles.
TextSession retains its existing font-only ownership. No cross-composition cache,
additional execution worker or authorizing proof is introduced.

Every logical part, including a reused one, charges its full width*height against
the original retained construction-pixel count. Check the current per-request
remaining pixel budget before accepting reuse; an insufficient budget has the
original text.capacity outcome. The final table construction check is unchanged.
Lookup exhaustion falls back to ordinary rendering, never admission refusal.
Requests with nonempty semantic blocks always render normally: their nested
retained-part accounting cannot be inferred from the completed raster alone.
Invalid/glyph/native/allocation failures retain the original behavior. Only a
successful zero-missing-glyph result may enter the bounded lookup. Full policy,
resource, frame and clear-before-paint validation still runs normally.

Before changing production code, freeze the existing backend's complete metadata,
cell rectangles and exact RGBA hashes for the literal table-raster fixture. Cover
duplicates, more than sixteen distinct parts, mixed identity/counter/Kind cells,
scale, contrast, transparency, distinct role fonts, semantic blocks, insufficient
remaining pixel capacity, invalid text after valid cells, and a changed second
composition. Preserve the exact source/binary/runtime and original raw pixels.
These equivalence expectations supplement independent table/role/native-pixel
oracles; never regenerate them from the candidate.

Compare both ordinary and shared-TextSession fixture calls with the frozen
expectations, including refusal without partial output. Run SCENE-TABLE,
TABLE-ERASURE, ROLE-COMPOSITION, TEXT-SESSION, chart/frame/image/visibility and
inspector regressions, then the unchanged ordinary table family and complete phase

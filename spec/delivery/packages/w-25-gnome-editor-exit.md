# Independent editor exit on the owned GNOME desktop

This W-25 experiment composes the existing native exit owner with the actual owned
GNOME/DING shell, persistent controller, supervised real collector and measured
passive tile. It closes the desktop lifetime/input integration prerequisite. The
transient candidate contains public fixed pixels; W-08/W-09/W-10 still own actual
scene drafts, transactions and persistence. No Apply/Cancel result is invented.

## Admission, interfaces and ownership

Extend the existing `GNOME-CONTROLLER-RECOVERY-01` family with five explicit editor
controls. Preserve all earlier controls and their oracles. The same bootstrap owns
the private display, buses and process groups. It launches one independently owned
`SysPane.EditorExitProbe --owned-gnome-lab` only after an observer request, retaining
its exact process. The observer holds native handles before any fault. Neither the
controller nor shell owns that recovery process. The latter owns only its self-child.

The GNOME variant requests an ordinary maximized transient candidate through native
window-manager hints, leaving the passive wall unchanged. The existing GTK recovery
button requests above-window placement. Exact native geometry, PID/resource identity
and observed pixels decide whether the candidate actually obstructs the icon fixture
and whether the button can be reached. A placement hint is never success evidence.
The original owned-Xvfb variant and its nine cases remain unchanged.

The selected candidate uses GTK's normal toplevel and requests maximization both
before showing and on its native map event. Initial hints alone left the tested
window beside the icon; those failed attempts remain evidence. The mapped request
is an implementation choice, never a substitute for observed obstruction.

Use the existing typed development policy and live render-health path. Collection
and passive rendering are neither restarted nor replaced to simulate recovery.
The same source epoch, original measured snapshots, controller, shell and icon-manager
lifetimes must survive. Desktop collection and editor release are separate observations.

## Fixed native cases

| Control | Fault/stimulus and required outcome |
|---|---|
| editor-key | Stop the held candidate; Ctrl+Alt+Escape through the independent owner releases it. |
| editor-button | Stop the held candidate; click the verified native GTK recovery button to release it. |
| editor-owner-loss | Stop the candidate, then kill only its held recovery owner; parent-death protection releases the obstruction. |
| editor-controller-freeze | Stop the candidate and independent controller, then use the keyboard exit; release succeeds before the observer resumes the controller. |
| editor-no-exit | Stop both candidate and recovery owner, then send the same key chord. The live obstruction remains and the candidate fails recovery acceptance; cleanup afterward is never counted as recovery. |

Each run first independently verifies baseline icon selection/clear and at least
2,000 ms of original measured counter/rate and advancing-age pixels. Require actual
candidate pixels over the independently located icon and a blocked click before
fault injection. Freeze confirmation comes from native process state, not an
application acknowledgement. The current input owner and its exact child are bound
to executable and parent identities before signals.

Positive recovery requires held child exit and disappearance of its obscuring pixels
within 1,500 ms of the stimulus, then independently verified native icon selection
within 2,500 ms. Resume a stopped controller only after the independent exit/pixel
observation, retaining that ordering. Clear selection, then capture at least 2,000 ms
of current original measured pixels using the existing glyph/age oracle and native
settings/icon anchors. Require acquisition before, during and after the obstruction,
no source/consumer replacement or recovery fault, and fresh render completions after
release. The negative control observes the still-live obstruction for 2,000 ms;
its expected failed candidate result requires healthy ongoing collection and shell.

## Bounds and evidence

Retain the exit owner's 15-second safety limit, 250 ms cooperative grace and exact
held-child escalation. The experiment must finish positive/negative acceptance
before that safety timer can supply an unintended exit. Retain the bootstrap's
70-second total bound, immutable source archive, exact native build identities,
private operational journals/crops and complete owned-group cleanup. Add no user
desktop, global shortcut installation, elevation or release operation.

Operational pixel/source evidence remains in mode-0600 files in the owned mode-0700
workspace. Public records contain synthetic input/lifetime facts, hashes and scoped
outcomes. Revalidate original journals and native cleanup independently; retain
every failed attempt and source version. Altered deadlines or weaker pixel/input
oracles require an explicit contract change, not an observer workaround.

# Native conditional presentation experiment

Implement conditional rendering for all seven primitive kinds in the existing
Linux SceneSurface owner. Use an explicit trusted SurfaceConfig development
opt-in, default false. Authoring/resource capability alone remains insufficient;
the existing scene 0.5 refusal tests keep their meaning without this opt-in.
Do not enable the option in ordinary editor or installed entry paths until private
controls, selection/gesture behavior and their independent native tests are complete.
This experiment advances W-09; it does not complete W-10 or any release edition.

## Owner and measurements

First compose and measure authorized content using the existing bindings, theme,
chart history, table alignment and image worker. Resolve layout as if all content
were shown. Then consume project_scene_visibility inside its synchronous borrow
and transform the unpublished candidate. Never query DataView from that callback.
The serialized SceneSurface prevents publication/policy/configuration changes
between the two phases. Content and condition permission checks both remain
mandatory; a hidden ancestor cannot bypass content validation or authorization.

Condition changes alone never remove a node, change a layout metric, collapse
space or alter authored selection. Content changes may still change its normal
measurement. Collection demand and authorized bounded chart/image work continue
while hidden, so conditions can reveal current content. Changing a rule through
replace retains the existing history/image reset behavior. Policy revocation,
disconnect, restart, failed native clear and shutdown retain their existing owners.

The existing policy/erasure owner now admits a presented/diagnostic flag and
status-only strings in its frame. These derived results never leave its protected
paint callback except in the registered native cache. Every mutating call/paint
clears that cache first. No independent visibility cache or retained evaluator
result is permitted. Policy denial erases frames, image work and chart history.

## Hidden content and mandatory status

A hidden primitive has no value/text/table/chart/image presentation, font list or
pixels. It remains in the layout with the same identity and bounds. Its frame
entry is marked not presented; title and accessible content are empty unless a
mandatory diagnostic replaces it. The editor's separately authorized authored
object list remains the route for selecting it.

Capture status separately from content formatting. For value/status/table/chart,
preserve selection errors and observation states other than Current, Derived and
Configured. Include only the existing safe provider error code, never its message
or the hidden value/unit/identity. Deduplicate identical status lines in encounter
order. A table without rows has the static notice "Table has no rows"; other table
selection failures preserve their existing summary. Chart gap, truncation, clipping
and explicit chart faults remain notices without points/ranges/counts. Hidden images
retain "Image loading" or "Image failed", without asset identity or alt text.

For hidden leaves, paint these mandatory notices even when the condition is false.
For shown leaves, their existing complete rendering remains unchanged. Core host,
replay and policy status remains independently owned; predicates cannot gate it.

## Unresolved conditions and groups

Use the shared preorder and diagnostics unchanged. Each unresolved condition has
the text "Visibility (ID): LABEL", with the authored ID and these exact labels:
Waiting, No match, Unsupported, Ambiguous, Invalid, Capacity, Source lost,
Unavailable, Stale, Unit mismatch, Type mismatch. Denied restricts the whole scene;
batch capacity yields alternative/surface.capacity without a frame.

Each node inherits unresolved diagnostic lines along its root-to-node path,
including paths through false conditions. Add its own unresolved line last, then
its independent mandatory status lines. Join lines with LF. A diagnostic replaces
the conditional payload: text is those lines; accessibility is the authored title,
one LF and those lines. Table/chart/image metadata is absent. Mark it presented
and diagnostic. A false ancestor cannot remove a child's unresolved status.

Groups retain the existing no-painted-header geometry. Relay group diagnostics to
each descendant leaf, within that leaf's retained bounds. Group accessibility also
contains its diagnostic. An empty group paints its diagnostic within its own bounds.
Ordinary hidden groups have no accessible row; visible diagnostic descendants are
promoted to the nearest presented ancestor or root in the inspector, preserving
their stable keys and preorder. Validate all nodes, including hidden nodes.

Use the current native font/theme/contrast and wrap diagnostic text to the retained
pixel width less its existing two guard pixels. Diagnostic rasters must fit wholly
inside the existing node rectangle; never enlarge, silently clip or ellipsize them.
Insufficient space or intersecting diagnostic raster rectangles returns the atomic
alternative surface.visibility_layout. Paint ordinary content first, then diagnostic
rasters in preorder, so ordinary authored content cannot overpaint a warning.
Existing pixel/text budgets include every retained diagnostic byte/pixel. A frame
with a conditional diagnostic is degraded, with reason visibility.diagnostic.

## Verification and remaining admission

Freeze this package and exact text/presentation examples before production edits.
Observe all kinds, same-source/group rules, hidden-parent unresolved children,
unchanged bounds, empty groups, wrapped/overflowing/overlapping warnings, failed
content, chart/image continuation, policy regrant and erasure. The inspector must
contain no hidden values, chart points, table identities or image alt/asset content.
Use the existing independent owned-X11 pixel and AT-SPI laboratory, including
inverted-predicate and retained-content controls. Keep original failures and exact
source/artifact identities within the existing workspace bound.

Private rule controls, ordinary editor admission, authored-list selection, held
gestures, save/reopen and lost-acknowledgement/restart native integration remain the
next required boundary. The shared stored-rule recovery is retained. W-09/W-10,
typography, clipboard/recovery drafts, installed ownership, other adapters and all
five complete release editions remain open until their own evidence passes.

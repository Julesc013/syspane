# Installed scene inspector ownership

Continue W-11 using the common Linux frontend, SceneInspector, SceneSurface and
the existing verified helper worker. Add no executable, protocol, scheduler or
alternate source tree. This package connects saved-profile inspection; completing
W-11 still requires authenticated inspector telemetry and the remaining native
platforms, accessibility/performance qualification and installed policy deployment.
An absent producer must remain an explicit unsupported binding, never fabricated
live data. The default scene therefore has Network and Network interfaces rows,
with Unsupported field for the table and no entity rows.

## Closed implementation boundary

The ordinary window has Settings, Edit scene and Inspect scene navigation. All
three use one current authenticated console profile. Selecting another mode
reloads that profile, clears the previous controls and waits for their cancelled
image/editor tasks before destroying them or constructing the next consumer.
Settings/private fields, dirty drafts, recovery offers and submitted/unknown
requests retain their existing can-leave rules for both navigation destinations.
Inspection itself is read-only and may be left during image loading; cancellation
must drain first. A saved revision is inspected only after a fresh profile load.
Never promote an uncommitted editor draft into the inspector.

Construct the inspector with the exact saved authored pair and immutable resource
snapshot, native topology and current capabilities/policy. Retain existing scene
0.5/theme 0.2 capability admission. The inspector uses inspector and accessibility
grants, plus history for charts, under its existing rules. The frontend supplies
its verified ImageFactory; a refused factory must not fall back to a pathname
worker. Existing component callers may continue to supply a worker path.

Reuse the frontend's 20-ms timer. Paint the read-only inspector at most once each
100 ms (and on initial load/topology change) to collect asynchronous image results.
All existing frame/model/image/resource limits remain fixed. Native topology
failure clears the inspector and reports unavailability; a subsequent topology
change permits a fresh profile-bound construction. No desktop visibility claim
follows from inspection. Unsupported render/layout states show an explicit
unavailable message instead of an apparently successful empty inspector.

Policy withdrawal and disconnect clear rows, selection and requested summary
within the existing owner operation. Independently observe erasure within 200 ms
of confirmed controller loss. Reconnection reconstructs from the new authenticated
profile. Shutdown clears controls immediately, then waits for backend stop and
all cancelled image jobs before exiting. No clipboard export is added.

product edits. Through a relocated ordinary-entry fixture, independently observe
exact GTK/AT-SPI rows, native keyboard summary, save/reopen, all navigation guards,
reload, policy loss, distinct controller replacement and clean exit. An intentionally
wrong row expectation must fail the same row observer. Preserve the baseline
failure when Inspect scene is absent. Reuse the installed editor's exact independent
saved-document/resource oracle; tests must not derive expectations from output.

Verify injected image-task ownership separately in the native inspector component:
exact encoded input, loading/ready content, cancellation and delayed reap before
destruction. Retain existing inspector channel, identity, keyboard, image and

GUI timing cases; keep original limits and failures. Large-input inspector latency,
real telemetry, protected deployment and complete editions remain separate gates.
